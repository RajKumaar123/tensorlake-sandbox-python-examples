# Engineering Principles

## Core Principles

- Build incrementally
- One milestone at a time
- Every milestone must compile
- Every milestone must execute
- Every milestone must be documented
- Every milestone must be committed to Git
- Every milestone must be independently testable
- Reuse Examples 01-12 where appropriate
- Keep sandbox as the execution boundary
- Prefer composition over inheritance
- Keep functions small
- Avoid duplication
- Follow PEP 8
- Document engineering decisions
- Keep architecture modular
- Add tests continuously
- Never skip documentation
- Keep README updated
- Keep outputs reproducible

## Additional Principles

- Favor explicit contracts over implicit behavior
- Keep Tensorlake-specific logic isolated
- Preserve artifact provenance
- Treat generated code as untrusted until verified
- Capture failures as part of the engineering record
- Use the simplest design that satisfies the milestone
- Add abstraction only when repetition or complexity justifies it
- Keep prompts, outputs, and artifacts versionable
