# Architecture

## Purpose

This document will describe the system architecture for Tensorlake Intelligence Hub.

## Design Goals

- Keep the architecture modular
- Separate orchestration from execution
- Keep sandbox interactions isolated
- Preserve state across sessions where needed
- Make every workflow reproducible

## Planned Layers

### Configuration
Loads environment settings, runtime options, and project metadata.

### Sandbox Management
Encapsulates sandbox lifecycle behavior and safety checks.

### Orchestration
Coordinates agents, tools, and workflows.

### Agents
Specialized components that will handle research, writing, review, and recovery tasks.

### Tools
Reusable integrations for files, browser interaction, and code execution.

### Memory
Persistent project state and research history.

### Outputs
Reports, logs, diagrams, and artifacts generated by the system.

## Architecture Notes

The foundation is intentionally lightweight. Detailed implementation decisions will be recorded as the project evolves.

## Additional Structure Guidance

The Python package should live under `src/insight_forge/` so imports remain clean and the project can grow without flattening the source tree.

The immediately existing folders should be limited to the foundation needed for Milestone 1:

- `src/`
- `docs/`
- `tests/`
- `outputs/`
- `diagrams/`
- `screenshots/`

Folders that should be added only when first needed:

- `agents/`
- `tools/`
- `memory/`
- `workflows/`
- `prompts/`
- `examples/`

This keeps the scaffold lean and avoids empty structure that has no implementation yet.
